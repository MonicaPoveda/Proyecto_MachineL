CRISP-DM Methodology · Phase 05 of 06

Evaluation

Performance analysis of the redesigned phishing classifier (Random Forest) against the original problem: false positives on legitimate URLs.

1. Model Overview

Algorithm: Random Forest (winner) — compared against SVM (RBF) and Decision Tree

Dataset: 9,626 balanced URLs (4,813 malicious + 4,813 legitimate)

Train/Test Split: Stratified 80% (7,700) / 20% (1,926)

Selection metric: F1-score on the held-out test set

Features: 31 lexical and syntactic characteristics

Target: is_phishing (0 = Legitimate, 1 = Phishing)

Threshold: 0.5

Sources: datos.gov.co IoC + top-1m.csv

3. Model Comparison

Three algorithms were trained and evaluated on the same stratified held-out test set (1,926 URLs). The winner was selected by test F1-score.

Model F1 Precision Recall Accuracy
Random Forest 🏆 99.74% 99.79% 99.69% 99.74%
Decision Tree 99.74% 99.79% 99.69% 99.74%
SVM (RBF) 99.64% 99.79% 99.48% 99.64%

Why Random Forest won: Random Forest and Decision Tree both reached F1 = 99.74%, but Random Forest was selected as the final model because, as a bootstrap-aggregated ensemble of many trees, it is more robust and less prone to overfitting than a single Decision Tree. It also slightly outperformed the RBF SVM (99.74% vs. 99.64% F1), which additionally scales worse as the dataset grows.

Interpretation: Out of 1,926 test URLs, only 5 were misclassified. The 2 False Positives are legitimate URLs incorrectly flagged as phishing (minor nuisance: an unnecessary warning). The 3 False Negatives are phishing URLs that were missed (the real security risk, but very low at 0.16%).

5. Original Problem Verification (False Positives Fixed)

The previous implementation misclassified legitimate URLs such as https://www.google.com and https://www.youtube.com as phishing. The redesigned model fixes this bug:

URL Classification Phishing probability
https://www.google.com ✅ Legitimate 10.9%
https://www.youtube.com ✅ Legitimate 10.2%
https://www.facebook.com ✅ Legitimate 6.2%
http://web071zoom.us/fix/audio-fv/7217417464 (IoC) ⚠️ Phishing 97.8%
http://layer-check.dervishpeel.in.net/verification.google (IoC) ⚠️ Phishing 96.0%
http://83.142.209.203:8080/hangup.wav (IoC) ⚠️ Phishing 100.0%

Legitimate top sites are now classified as legitimate, while real malicious URLs from the datos.gov.co IoC feed are still detected as phishing with high confidence.

6. Methodological Note

  • 31 lexical and syntactic features: URL/host/path/query lengths, dot/hyphen/digit counts, subdomain count, path depth, query parameters, presence flags (IP host, "@", non-standard port, punycode, shortener, executable extension, risky TLD), character entropy, longest host token, suspicious tokens and brand impersonation.
  • HTTPS extracted correctly: the URL normalizer now preserves the scheme, so has_https carries real signal (the old implementation forced every URL to http://).
  • Token matching instead of substring matching: suspicious words (login, verify, account, support…) are matched as whole hostname tokens, which avoids flagging legitimate URLs such as accounts.google.com or support.microsoft.com.
  • Held-out test set + confusion matrix: model selection used a stratified 80/20 split and the confusion matrix was inspected, instead of relying only on cross-validation, to detect overfitting.

7. Errors and Limitations

  • Only 5 misclassified URLs: 2 false positives and 3 false negatives on the held-out test set.
  • Distribution-specific training: the model was trained on top-1m (legitimate) and datos.gov.co IoC (malicious). Performance on unseen real-world URLs may be lower.
  • Brand-impersonation gap: synthetic brand-impersonation patterns not present in the IoC feed may be missed (e.g. a handcrafted paypal-verify-*.tk URL was not flagged).
  • Artificial balance: the dataset is 50/50 balanced, while phishing is less frequent in the real world.
  • Threshold 0.5: a lower threshold would increase recall but also false positives.

8. Final Model Selection

The Random Forest model is selected as the final model for this phase, with the following justifications:

  • Strengths: best F1 (99.74%), only 2 false positives and 3 false negatives, robust ensemble that resists overfitting, and provides probability estimates for the phishing class.
  • Resolved the original bug: legitimate URLs (Google, YouTube, Facebook) are no longer flagged as phishing, while real IoC malicious URLs remain detected.
  • Next steps: cover brand-impersonation patterns and evaluate on a broader, real-world URL sample before production hardening.

Final decision: the Random Forest model is accepted and deployed in the Platform page, replacing the previous Logistic Regression baseline.
