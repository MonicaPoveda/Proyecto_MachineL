CRISP-DM Methodology · Phase 01 of 06

Business Understanding

This project develops a web application that estimates how likely a submitted URL is to be phishing. It returns a risk estimate with a plain-language explanation: probable phishing, probable legitimate, or undetermined.

Problem definition

Users have difficulty judging unfamiliar links

Phishing links can imitate trusted organizations and lead users to disclose credentials, financial details, or personal information. Blacklists may not yet contain newly reported links, and technical scanner results can be hard for non-specialists to interpret.

The project addresses this problem: a user submits a URL, the application analyzes the characteristics of the link itself, and it returns an understandable risk estimate. The application analyzes links only; email addresses, email messages, and message content are outside its scope. A page preview is a supporting feature, not proof that a site is safe or malicious.

Business objective

Support safer decisions

The objective is a web-based machine-learning application that classifies a submitted URL as probable phishing or probable legitimate, shows the probability behind that result, explains the main reasons in plain language, and offers cautious next-step guidance.

It is aimed at people who need a quick, accessible first check. The application is a decision-support tool and does not replace security software or expert investigation.

Result shown to the user

What the application reports

The application estimates a probability that a URL is phishing and presents it as one of three outcomes. The result is always an estimate: the application never states that a link is safe or confirmed legitimate.

OutcomeMeaningWhat the user sees
Probable phishingThe estimated phishing probability is high.A warning, the probability, the main characteristics that raised the risk, and advice not to open or enter data on the link.
UndeterminedThe estimate falls in an intermediate range where the model is not reliable enough to decide.A caution message, the probability, and guidance to verify the link through an official channel.
Probable legitimateThe estimated phishing probability is low.A low-risk indication with a reminder that this is not a guarantee of safety.

The thresholds that separate the three outcomes are set during the evaluation phase. A match with a known malicious indicator takes priority over the model's estimate.

Project objectives

What the project aims to deliver

  • Build a binary classifier that estimates whether a submitted URL is phishing, using characteristics of the URL itself such as length, structure, subdomains, special characters, and suspicious words.
  • Return a probability and one of three outcomes (probable phishing, undetermined, probable legitimate) instead of an absolute verdict.
  • Explain each result in plain language by showing which characteristics contributed most to the estimate.
  • Evaluate the model with metrics that expose weaknesses in each class, and report results separately for different URL forms so that strong performance on easy cases does not hide weak performance on hard ones.
  • Never label a URL as safe or confirmed legitimate; always communicate the uncertainty of the estimate.
  • Offer a page preview through a controlled, isolated mechanism that does not expose the user or the application server to the submitted site.

Business needs and boundaries

Requirements

  • Usability: the application accepts a URL and shows an understandable result without requiring cybersecurity expertise.
  • Timeliness: the estimate is returned promptly, and the user is told when analysis is unavailable.
  • Privacy: retention of submitted URLs is minimized, and the application does not collect credentials or browse as the user.
  • Preview safety: previews run in an isolated sandbox or trusted preview service; the application server never fetches arbitrary submitted URLs.
  • Transparency: the application states that predictions can be wrong, that "probable legitimate" is not a safety guarantee, and what the model's limitations are.
  • Scope: only web URLs and links are assessed. Email addresses, email messages, and message content are not analyzed. The application is not a general malware scanner or a guarantee of site reputation.

Model decision

Binary classification with a probability score

Logistic Regression is the main algorithm. It classifies a URL as phishing or not phishing and produces a probability that drives the three outcomes shown to the user. Support Vector Machine is an optional comparison.

The model estimates similarity to the patterns of known phishing links; it does not verify who owns a site or what it contains, so a low score does not prove legitimacy. K-means may be used to explore groups of similar URLs, but a cluster is not a label. Only the permitted algorithms are used.

Success criteria

Acceptance measures

These are the initial targets set for the project. They are goals, not measured results, and will be reported against the final model in the evaluation phase.

AreaProposed criterionWhy it matters
DetectionPhishing-class recall ≥ 0.80 on a held-out test setMeasures how many phishing links are missed.
TrustworthinessPhishing-class precision ≥ 0.85 and false-positive rate ≤ 0.05Reduces unnecessary warnings on legitimate links.
EvaluationConfusion matrix, per-class precision/recall/F1, and ROC-AUC, reported overall and by URL formPrevents accuracy alone from hiding weak results on harder links.
Honest reportingEvery result carries a probability and a stated limitation; no URL is reported as safePrevents users from reading a low score as a guarantee.
User experienceA clear outcome, the main reasons, limitations, and a safe-preview statusHelps users act without implying certainty.
Safety and privacyNo direct server-side visit to submitted URLs; documented retention and preview controlsReduces exposure to malicious content and unwanted data collection.
