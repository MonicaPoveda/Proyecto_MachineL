CRISP-DM Methodology · Phase 01 of 06

Business Understanding

This project develops a web application that checks a submitted URL against known threat information from the Indicators of Compromise (IoC) published by Colombia's MinTIC / ColCERT. The application can report a URL as malicious or as unknown; it cannot confirm that a URL is legitimate.

Problem definition

Users have difficulty judging unfamiliar links

Phishing and other malicious links can imitate trusted organizations and lead users to disclose credentials, financial details, or personal information. Blacklists may not yet contain newly reported links, and technical scanner results can be hard for non-specialists to interpret.

The project focuses on this problem: a user submits a URL, the application analyzes it against the threat data it holds, and it returns an understandable result. The application analyzes links only; email addresses, email messages, and message content are outside its scope. A page preview is a supporting feature, not proof that a site is safe or malicious.

Business objective

Support safer decisions

The objective is a web-based machine-learning application that checks a submitted URL, reports whether it is malicious according to the available threat data, identifies the threat category when possible, and explains the result in plain language with cautious guidance.

It is aimed at people who need a quick, accessible first check. The application is a decision-support tool and does not replace security software or expert investigation.

Scope of the result

What the application can and cannot determine

The application cannot determine with certainty that a URL is benign or legitimate. Its data source contains only threat-related indicators and no verified legitimate URLs, so the absence of a URL from that data says nothing about whether the URL is safe. For every submitted URL, the application returns one of two outcomes:

OutcomeMeaningBasis
MaliciousThe URL, or its host, matches a known indicator, or the model classifies it into a supported threat category.MinTIC / ColCERT IoC records and their threat tags.
UnknownThe application has no evidence about the URL. It is not reported as safe, benign, or legitimate.No matching indicator and no supported threat classification.

Project objectives

What the project aims to deliver

  • Use the URL records of the MinTIC / ColCERT IoC dataset, together with their threat tags, to identify supported threat categories for submitted links.
  • Assess the quality of the data, prepare URL features, and keep duplicate or related domains from leaking across training and evaluation splits.
  • Train and evaluate a classifier for the URL categories that have sufficient labeled examples, using Logistic Regression as the main algorithm.
  • Report each URL as malicious (with its threat category and a confidence or risk score where validation supports it) or as unknown, together with practical safety recommendations.
  • Never label a URL as legitimate, safe, or benign, because the available data cannot support that conclusion.
  • Offer a page preview through a controlled, isolated mechanism that does not expose the user or the application server to the submitted site.

Business needs and boundaries

Requirements

  • Usability: the application accepts a URL and shows an understandable result without requiring cybersecurity expertise.
  • Timeliness: the assessment is returned promptly, and the user is told when analysis is unavailable.
  • Privacy: retention of submitted URLs is minimized, and the application does not collect credentials or browse as the user.
  • Preview safety: previews run in an isolated sandbox or trusted preview service; the application server never fetches arbitrary submitted URLs.
  • Transparency: the application states that an "unknown" result is not a safety guarantee, that predictions can be wrong, and what the data and model limitations are.
  • Scope: only web URLs and links are assessed. Email addresses, email messages, and message content are not analyzed. The application is not a general malware scanner or a guarantee of site reputation.

Model decision

URL threat tags as candidate classes

The URL records of the IoC dataset include a tags field with threat categories, which the project uses as candidate classes. Logistic Regression is the main algorithm for classifying URLs among these categories, and Support Vector Machine is an optional comparison. The data is strongly imbalanced, so predictions for rare tags are expected to be less reliable.

Because the IoC feed contains no legitimate URLs, the model is not a malicious-versus-legitimate detector and cannot certify a link as safe. K-means may be used to group URL patterns by similarity; a cluster, or a URL far from every cluster, is neither a verified threat label nor proof of legitimacy. The dataset's IoC type values describe indicator formats, not risk classes. Only the permitted algorithms are used.

Success criteria

Acceptance measures

These are the initial targets set for the project. They are goals, not measured results, and will be reported against the final model in the evaluation phase.

AreaCriterionWhy it matters
DetectionPer-class recall and macro-F1 across the supported threat categories on a held-out test setMeasures missed threats and performance across categories.
EvaluationConfusion matrix, per-class precision/recall/F1, macro-F1, and class distributionMakes imbalance and category trade-offs visible instead of relying on accuracy alone.
Honest reportingEvery result is either malicious or unknown; no URL is ever reported as legitimate or safePrevents users from reading a missing match as a safety guarantee.
User experienceA clear result, stated limitations, and a safe-preview statusHelps users act without implying certainty.
Safety and privacyNo direct server-side visit to submitted URLs; documented retention and preview controlsReduces exposure to malicious content and unwanted data collection.
