CRISP-ML(Q) Methodology · Phase 05 of 06

Model Deployment

Integration of the selected URL classifier into the authenticated web platform, with clear outputs, user guidance, and deployment requirements.

Model implementation

Trained model and prediction loading

Models are trained outside the prediction request flow using the model-engineering process. This process saves serialized models in outputs/phase4_output/models/, together with outputs/phase4_output/model_comparison.csv and outputs/phase4_output/modeling_metadata.json. The platform selects the model with the highest mean cross-validation F1; based on the current results, it selects Random Forest.

When the first prediction request is received, the application loads the selected model and reuses it for subsequent requests. It does not retrain the model for each URL. The Phase 3 selection by cross-validation does not replace the final evaluation using the reserved Phase 4 test set.

Application integration

URL analysis workflow

  1. An authenticated user submits a URL through the platform page; the submission is protected by the application's request validation.
  2. The application validates and normalizes the input, then extracts the features expected by the model.
  3. The model classifies the URL as possible phishing or probably legitimate and, when available, calculates an estimated phishing probability.
  4. The page displays the result and, for Random Forest, summarizes conditions on the decision paths. These are supporting model details, not causal explanations.
  5. The model analyzes URL text only; it does not fetch the destination or query live IoC or reputation sources for the prediction.

If model artifacts are missing or the expected features do not match, the application reports that prediction is unavailable instead of generating a fallback result.

Using the results

Decision support

The result helps users decide whether to treat a URL with caution. A possible phishing alert should prompt them not to open the link or enter information; a probably legitimate result should not be interpreted as a safety certification.

The tool analyzes URL features and does not replace antivirus software, reputation lists, or a specialist investigation.

Browser preview

Restricted HTTPS preview

The platform can preview a public HTTPS URL in a sandboxed iframe in the user's browser. It is not a remote browser or server-side screenshot: the user's browser connects to the destination. Local/private addresses and non-HTTPS URLs are not previewed.

The preview is untrusted content, not a safety check. Some sites block embedding, and users should never enter credentials into a previewed page.

Deployment environment

Configuration and persistence

The service is configured for deployment on Render with Gunicorn. Render's default filesystem is ephemeral, so model artifacts must be included in the deployment or retrieved from persistent storage. The application uses PostgreSQL when DATABASE_URL is configured and SQLite for local development. Account persistence and model-artifact availability should be checked after deployment and restart.

Next CRISP-ML phase: monitoring indicators, drift checks, incident feedback, and controlled model updates are described separately in Phase 06: Monitoring and Maintenance. These are proposed practices; automated production monitoring is not currently implemented.
