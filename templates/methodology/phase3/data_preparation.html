CRISP-DM Methodology

Phase 03: Data Preparation

Documentation of data cleaning, class balancing, feature engineering, and data splitting processes to prepare the mathematical matrix for the Machine Learning model.

Phase Objective

Transforming Raw Indicators into a Trainable Dataset

Pipeline Execution

Data Processing Workflow

1

Selection and Cleaning

The pipeline loads indicators_of_compromise_ioc_20261106.csv and urls_leg.csv. From IoC it keeps only URL and FQDN records; urls_leg.csv contributes URLs labeled legitima.

Both sources are normalized with the same features.py logic. Invalid URLs are removed and duplicate normalized URLs are collapsed; IoC labels take priority if a URL appears in both files.

2

Class Balancing (50/50)

IoC URLs and domains are labeled phishing (1), while URLs in urls_leg.csv are labeled legitimate (0). The pipeline balances the combined data by randomly sampling the larger class.

The resulting unified dataset contains an equal number of phishing and legitimate examples and is shuffled before feature extraction.

3

Feature Engineering

Machine Learning algorithms cannot process raw text. Using the features.py module, the system iterated over every URL to extract 31 mathematical and lexical features.

This process was performed exclusively on the text string (without making HTTP requests), extracting data such as character entropy, suspicious keyword counts, symbol ratios (-, @, _), and risky TLD identification.

4

Data Splitting (Train/Test)

The final numerical matrix was divided to prepare for the Modeling Phase. Using scikit-learn, a stratified split was applied to ensure the 50/50 class balance remained intact across both partitions.

80% of the data was exported to train.csv (for model training), and 20% was securely isolated in test.csv (to validate accuracy on unseen data).

Extracted Features (Mathematical Matrix)

Below are the key categories of the 31 numerical features engineered from the raw URL strings to feed the classification algorithms.

Structural Constraints

url_length, n_dots_url, path_depth. Measures excessive subdomains and lengths used to hide true domains.

Social Engineering Indicators

host_n_hyphens, n_suspicious_words. Detects brand spoofing attempts (e.g., "login-secure") and urgency keywords.

Evasion & Entropy

url_entropy, has_ip_host. Identifies randomly generated DGA domains, raw IP usage, and risky TLDs (e.g., .xyz).

Phase 3 Output

Final Deliverables

The execution of the pipeline successfully outputted a clean, mathematically structured, and balanced dataset ready for Phase 4 (Modeling).

  • dataset_balanceado_completo.csv (Full matrix)
  • train.csv (80% Training Data)
  • test.csv (20% Validation Data)
