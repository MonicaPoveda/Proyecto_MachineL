CRISP-DM Methodology · Phase 05 of 06

Evaluation

Evaluate the Random Forest selected in Phase 4 on the reserved test set, compare it with the project objectives, and document its errors and limits.

1. Evaluation procedure

One final evaluation on data not used for model selection

  • Phase 3 created a stratified 80/20 split. Phase 4 trained and selected models using only train.csv.
  • Phase 4 used shuffled, stratified 3-fold cross-validation within the training set to tune and compare the candidate models.
  • The selected Random Forest is evaluated on outputs/phase3_output/test.csv, which was not used for Phase 4 selection.
  • The test set contains 8,484 rows: 4,242 legitimate and 4,242 phishing examples, with the same 31 features.
  • Metrics appropriate for binary classification include phishing precision and recall, F1, ROC-AUC, accuracy, false-positive rate, and the confusion matrix.

The results shown here were calculated from the current saved model and test file. The repository does not yet include a standalone Phase 5 evaluation script to regenerate this report automatically.

6. Risk analysis

Overfitting, underfitting, sampling bias, and scope

RiskEvidence and impact
OverfittingThe 2.90-point mean train-validation F1 gap indicates some overfitting. The similar held-out F1 is encouraging for this split, but random splitting may leave related domains or patterns in both partitions.
UnderfittingThe measured scores do not indicate obvious underfitting on this dataset. Performance on new domains, URL formats, and future samples has not been established.
Class prevalence and samplingThe test data is balanced 50/50, unlike typical production traffic. Precision and accuracy can change when phishing is much less common.
Label and data biasIoC and legitimate labels may be incomplete, stale, or noisy. Results may reflect the sources and collection period rather than all phishing URLs.
Feature and scope limitsThe model uses 31 lexical and structural URL features only. It does not inspect page content, redirects, live reputation, or site behavior.
Operational riskThe 235 false negatives show that some phishing URLs are missed; the 109 false positives can create unnecessary warnings. A prediction is not a safety guarantee.

7. Expert review

Domain-specialist validation is still pending

No specialist review is recorded in the current project artifacts. Before production use, security or threat-intelligence experts should review label quality, representative false positives and false negatives, URL-type coverage, and whether the decision threshold is appropriate for the intended users.

The project treats this review as a release check, not as a completed approval. This reflects the emphasis on rigorous real-world evaluation in the KDnuggets (2025) reference supplied for this evaluation.

8. Does the model address the problem?

A useful first-stage risk estimate, not a security guarantee

The Random Forest meets the stated recall, precision, and false-positive objectives on the available test set, so it is a suitable project candidate for URL triage. The result should still be treated as an estimate and combined with user caution and other security checks.

9. Final selection and next step

Random Forest selected for the project

Random Forest is selected because it achieved the highest mean cross-validation F1 among the three Phase 4 candidates and met the project thresholds on the reserved test set. The application loads this saved model from outputs/phase4_output/models/.

Before production use, evaluate on a newer independent sample split by domain and time. If that evaluation fails the objectives, return to data preparation or modeling and repeat the documented selection process.
