CRISP-ML(Q) Methodology · Phase 01 of 06

Understanding the Business and Data

This phase defines the phishing-risk problem, intended stakeholders, business and machine-learning objectives, data sources, constraints, and measurable success criteria. The current platform provides a binary URL estimate, not an undetermined outcome.

Problem definition

Users have difficulty judging unfamiliar links

Phishing links can imitate trusted organizations and lead users to disclose credentials, financial details, or personal information. Blacklists may not yet contain newly reported links, and technical scanner results can be hard for non-specialists to interpret.

The project addresses this problem: a user submits a URL, the application analyzes the characteristics of the link itself, and it returns an understandable risk estimate. Intended beneficiaries include people checking unfamiliar links and organizations seeking an initial signal. The application analyzes links only; email addresses, email messages, and message content are outside its scope. Potential consequences include credential theft, financial loss, exposure of personal information, and unauthorized account access.

Business objective

Support safer decisions

The objective is a web-based machine-learning application that classifies a submitted URL as possible phishing or likely legitimate, shows the estimated phishing probability, and presents available Random Forest path conditions. It is a decision-support tool and does not replace security software or expert investigation.

It is aimed at people who need a quick, accessible first check.

Result shown to the user

What the application reports

The application estimates a probability that a URL is phishing and presents it as one of two outcomes. The result is always an estimate: the application never states that a link is safe or confirmed legitimate.

OutcomeMeaningWhat the user sees
Possible phishingThe binary classifier predicts the phishing class.A warning, estimated phishing probability when available, and URL characteristics reflected in Random Forest tree paths.
Likely legitimateThe binary classifier predicts the legitimate class; this is not a safety certification.A low-risk estimate and a reminder that the URL may still be unsafe.

The current application uses the model's binary prediction. It does not implement a third "undetermined" outcome, calibrated risk bands, or a live lookup that gives IoC matches priority over the model.

Project objectives

What the project aims to deliver

  • Build a binary classifier that estimates whether a submitted URL is phishing, using characteristics of the URL itself such as length, structure, subdomains, special characters, and suspicious words.
  • Return a binary class and estimated phishing probability instead of an absolute verdict.
  • Present available Random Forest path conditions as supporting details, without treating them as causal explanations.
  • Evaluate the model using class-sensitive metrics and document that domain- and time-separated evaluation remains future work.
  • Never label a URL as safe or confirmed legitimate; always communicate the uncertainty of the estimate.
  • Offer a browser-side preview for public HTTPS URLs using a restricted iframe, while warning that the user's browser still connects to the destination.

Business needs and boundaries

Requirements

  • Usability: the application accepts a URL and shows an understandable result without requiring cybersecurity expertise.
  • Timeliness: the estimate is returned promptly, and the user is told when analysis is unavailable.
  • Privacy: retention of submitted URLs is minimized, and the application does not collect credentials or browse as the user.
  • Preview safety: the preview runs in the user's browser in a sandboxed iframe; it is not a remote browser or virtual machine, and the browser connects to the destination.
  • Transparency: the application states that predictions can be wrong, that "probable legitimate" is not a safety guarantee, and what the model's limitations are.
  • Scope: only web URLs and links are assessed. Email addresses, email messages, and message content are not analyzed. The application is not a general malware scanner or a guarantee of site reputation.

Model decision

Binary classification with a probability score

Logistic Regression, Random Forest, and Gradient Boosting were compared using stratified cross-validation. Random Forest was selected by mean F1 and is used by the current application.

The model estimates similarity to the patterns of known phishing links; it does not verify who owns a site or what it contains, so a low score does not prove legitimacy. SVM, K-means, multiclass threat categorization, and a third indeterminate class are not implemented in the current pipeline.

Data context

Sources, labels, and analytical questions

  • The IoC file contains 106,881 rows and 8 fields. The project pipeline uses IoC records of type URL and FQDN as the phishing class.
  • urls_leg.csv supplies the legitimate class. The repository also contains top-1m.csv, but it is not used in training or inference.
  • The target is is_phishing (1 = phishing, 0 = legitimate). IoC labels are source-provided threat labels, not independent confirmation that each URL is phishing.
  • Initial analysis found 55,288 exact duplicate IoC rows, 69,500 repeated values, one missing IoC type, and no benign class in the IoC source.

The model addresses three practical questions: does the submitted URL resemble phishing examples in the training data; what probability does the model assign to the phishing class; and what URL conditions appear in the selected Random Forest's decision paths? A detailed dataset profile is available in the supporting data-profile page.

The test data contains 8,484 rows, balanced 50/50. Its random record-level split does not establish generalization to unseen domains, future campaigns, or real-world phishing prevalence.
